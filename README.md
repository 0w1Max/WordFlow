# WordFlow

Приложение для изучения и долгосрочного запоминания слов — иностранных,
редких, профессиональных терминов и любых других понятий, которые хочется
не просто сохранить, а по-настоящему выучить с помощью интервальных
повторений.

Первая версия задумывалась как модуль будущей экосистемы **KeyStep**
(см. `events/` — задел на интеграцию через события, без прямой связки кода).

## Стек

- **Backend**: Node.js, Express 5
- **База данных**: [Turso](https://turso.tech) (облачный SQLite, доступ по HTTP через `@libsql/client`)
- **Авторизация**: email + пароль, JWT в httpOnly-cookie
- **Frontend**: чистый JS (ES-модули), без сборщика
- **Деплой**: Vercel (serverless-функция) + Docker (для локального запуска в контейнере)

## Быстрый старт (локально)

```bash
npm install
cp .env.example .env
# впишите в .env свои значения TURSO_DATABASE_URL / TURSO_AUTH_TOKEN / JWT_SECRET
npm run dev
```

Приложение поднимется на `http://localhost:3000`.

### Тесты

```bash
npm test
```

Юнит-тесты на встроенном `node:test` (без дополнительных зависимостей) —
покрывают алгоритм интервальных повторений, валидаторы и расстановку
переносов/ударений в словах.

### Нужна база в Turso

Проще всего — через [Vercel Marketplace](https://vercel.com/marketplace/tursocloud):
Storage → Create Database → Turso → Connect. Значения `TURSO_DATABASE_URL` и
`TURSO_AUTH_TOKEN` подставятся в проект автоматически. Для локальной разработки
их можно скопировать оттуда же или создать отдельную dev-базу через Turso CLI.

### JWT_SECRET

Обязательно задайте случайное значение перед деплоем в прод:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

## Запуск в Docker

```bash
docker compose --env-file .env up --build
```

## Деплой на Vercel

1. Подключите репозиторий к проекту на Vercel
2. Добавьте базу через Storage → Turso (см. выше) — переменные окружения подставятся сами
3. Добавьте `JWT_SECRET` вручную в Settings → Environment Variables
4. Задеплойте — `vercel.json` и `api/index.js` уже настроены, дополнительных правок не требуется

## Структура проекта

```
api/              — точка входа для Vercel (serverless-функция)
app.js            — Express-приложение (роуты, middleware, обработка ошибок)
server.js         — локальный запуск (app.listen), не используется на Vercel
config/           — конфигурация (порт, JWT, префикс API)
controllers/      — HTTP-обработчики
services/         — бизнес-логика (валидация, интервальные повторения и т.д.)
data/             — доступ к БД (Turso)
models/           — форма доменных объектов
routes/           — маршруты Express
middleware/       — auth, rate limiting, обработка ошибок, SPA-фолбэк
validators/       — проверка входных данных
errors/           — классы ошибок приложения
events/           — событийная шина (задел на интеграцию с KeyStep)
db/               — подключение к БД и миграции схемы
public/           — фронтенд (HTML/CSS/JS, ES-модули без сборщика)
tests/            — юнит-тесты (node:test, запуск: npm test)
```

## Текущий функционал (MVP)

- Публичная лендинг-страница (`/`) с демонстрацией концепции и пробным режимом
- Пробный режим без регистрации («гость») — сессия сохраняется в cookie,
  прогресс можно позже привязать к email/паролю без потери данных; при
  попытке выйти без сохранения гостю показывается отдельный экран
  подтверждения с предупреждением о потере слов
- Регистрация и вход (email + пароль), показ введённого пароля по клику
- Восстановление пароля по email (через Resend)
- Добавление слов со значением, примером, категорией и (опционально)
  ударением — конкретная буква отмечается кликом при вводе слова
- Корректный перенос длинных слов по слогам и грамотное отображение
  ударения на карточках, независимо от того, где браузер решит перенести
  строку
- Категории: создание, отображение, удаление
- Редактирование и удаление слов; кнопки сохранения/входа неактивны, пока
  не заполнены обязательные поля формы
- Повторение слов по расписанию (упрощённый алгоритм SM-2)
- Мониторинг ошибок через Sentry (опционально — без `SENTRY_DSN` просто отключён)

## Известные ограничения / что дальше

- Rate limiting считается "на инстанс" serverless-функции, а не глобально —
  для строгой защиты в высоконагруженном проде нужен store поверх Redis
  (например, `@upstash/ratelimit`)
- Нет полноценной интеграции с KeyStep — событийная шина (`events/`) готова
  принять реальные обработчики, когда экосистема появится
- Без своего домена в Resend письма шлются с `onboarding@resend.dev` —
  для продакшна стоит подтвердить собственный домен
